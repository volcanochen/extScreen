## 第二轮（23:00-23:30）：端到端打通，发现 4 个真 bug

### 结论：扩展屏链路已完全跑通
`电脑窗口 → VDD 虚拟屏 → Sunshine 编码 → Moonlight 解码 → 手机屏幕`
验证证据：手机视频区与 PC 虚拟屏逐像素平均差 <2，截图内容完全一致（记事本+画图窗口
都出现在手机上）。鼠标可无缝跨屏：`SetCursorPos` 打到 (7400,1100)/(8300,2100) 都精确
落在 `\\.\DISPLAY117`。

### Bug 1（致命）：service_state() 永远返回 None
`extscreen_core.py` 里 `OpenSCManagerW/OpenServiceW` 没声明 `restype`，64 位 Python 把
SC_HANDLE 截成 32 位 → `QueryServiceStatusEx` 必然失败。后果：
- 托盘永远红色、「Sunshine 未安装」
- `start_service()` 永远走启动分支，然后 `sc start` 在已运行时失败 → 报"启动 Sunshine 失败"
- **这就是用户一直说的"还是失败了"**
修法：声明全套 argtypes/restype（HANDLE）+ 用 SERVICE_STATUS_PROCESS 结构体。
同时把 `bind_sunshine_output` 里"改了配置要不要重启服务"的判断也修好了。

### Bug 2：DPI 虚拟化导致窗口"设置成功却不在屏幕上"
非 DPI 感知进程调 `SetWindowPos(7280,...)`，坐标被按主屏缩放二次放大送到屏幕外，
Windows 把窗口钳回主屏。`GetWindowRect` 还会**报回你输入的值**（假的）。
修法：进程启动即 `SetProcessDpiAwarenessContext(-4)`；exe 日志首行会打印 `dpi=per-monitor-v2`。

### Bug 3：三星 Game Booster 触摸锁吃掉所有 adb input
手机连上 Moonlight 后 `dumpsys window` 里出现 `GameBooster Lock Screen: isVisible=true`，
所有 `input tap` 全部无效，截图还异常发暗（半透明遮罩）。
`settings get secure game_touchscreen_lock` = 1。
修法：`settings put secure game_touchscreen_lock 0`（连带 `game_edgescreen_touch_lock`、
`game_pressure_touch_lock`）+ `am force-stop com.samsung.android.game.gametools`。
**以后调试手机端必须先查这三个设置。**

### Bug 4：Moonlight 强制横屏 → 竖屏串流被压成 525px 窄条
虚拟屏 1080x2220 竖屏时，Moonlight 的 Game Activity 仍把手机转成 2220x1080 横屏，
视频 fit 到高度后只剩中间一条，四周全黑（黑像素 76%）。
修法：虚拟屏改成 **2220x1080 横屏**（= 手机横屏分辨率），画面 1:1 铺满。
`user_rotation` / `accelerometer_rotation` 都改不动 —— 是 App 自己 requestOrientation。
Moonlight 被标记 `IS_GAME`，由三星 Game Booster 接管方向。

### 新增模块 src/extscreen_display.py（原生显示控制，替代 vdisplay.ps1）
- `set_dpi_aware()` / `enum_devices()` / `current_mode()` / `list_modes()`
- `find_vdd()` 按 desc 含 'vdd by mtt'/'virtual display driver' 识别虚拟屏
- `apply_mode(dev,w,h,fps,x,y)` 走 `ChangeDisplaySettingsExW`（CDS_RESET|CDS_UPDATEREGISTRY）
- `place(dev,w,h,...,position,align)` 支持 right/left/above/below × start/center/end，
  **对齐基准取主屏而不是所有屏的外接框**（否则主屏上方有副屏时会被顶到负坐标）
- `parse_sunshine_displays()` 从 sunshine.log 解析设备枚举 JSON 拿 `device_id`
  （Sunshine 只在启动时打印一次，尾部窗口要给 4MB；debug 日志涨得很快）
- `write_sunshine_output()` 幂等写 `output_name/stream_audio/min_log_level`，保留其它键

### 关键认知
- Sunshine 的 `output_name` 必须填 **device_id**（`{f3c4cd9e-b807-5109-a0f6-bb57ac9e7018}`），
  填 `\\.\DISPLAYxx` 报 Failed to find device
- device_id 由 EDID 序列号推导，**显示器改名（DISPLAY79→117）也不变**；DISPLAYxx 编号会变
- 改了 `output_name` 必须重启 Sunshine 服务才生效
- 改分辨率不用重启 Sunshine，它会自己打印 `Desktop resolution [WxH]` 跟着走
- 元凶之一：`min_log_level = debug` 会让 sunshine.log 疯涨，把枚举块挤出读取窗口 → 已改回 info

### 配置项扩展（config.json）
`resolution`（'auto' 或 'WxH'）、`orientation`（landscape/portrait，仅 auto 时用）、
`position`、`align`。设置窗口第一项改为「自动：跟随手机屏幕铺满」。
`target_resolution()` 用 `adb shell wm size` 读手机逻辑分辨率，横屏取 2220x1080。

### 守护
`poll_loop()` 加了看门狗：连续 3 次检测到虚拟屏掉线且服务在跑 → `restart_vdd()`，5 分钟冷却。

### 环境坑（补充）
- 沙箱里 `python -c "...Popen(['notepad'])..."` 启动的窗口**命令结束就被连带杀掉**，
  所以"移过去的窗口抓不到"其实是窗口已经死了。验证必须把「启动+移动+截图」放在同一条命令里。
- 从管理员 cmd 用 `start` 起的进程是提权进程，非提权 Python **无法 SetWindowPos**（UIPI 静默忽略）。

  要恢复只能重启 exe。
- `printf` 写 Windows 路径会把反斜杠啃掉（`\V` → `//`），要用单引号 heredoc 或 `\\` 转义。
